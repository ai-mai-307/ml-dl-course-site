# ml-dl-course-site
Материалы курса "Классическое машинное обучение" и "Глубокое машинное обучение" в виде сайта

## Новая версия: Astro + Starlight

Scaffold находится в корне репозитория, в ветке `site-v2`.
Текущий MkDocs-сайт в `docs/` и его workflow публикации сохраняются без изменений.
Сборка Astro попадает в `dist/`, сборка MkDocs — в `site/`.
Vite не наблюдает за `.venv/`, `.tools/`, `site-v2-starter/` и `site/`,
чтобы служебные файлы и старое окружение не задерживали запуск dev-сервера.

Требуется Node.js 22.12+ поддерживаемой чётной ветки; рекомендуется Node.js 24 LTS
(см. `.nvmrc`). Зависимости зафиксированы в `package-lock.json`.
TypeScript 6 используется из-за peer dependency `@astrojs/check`: версия 7 пока не поддерживается.

```sh
npm ci
npm run dev
```

Открыть: <http://localhost:4321/ml-dl-course-site/>.
Префикс соответствует текущему адресу GitHub Pages; публикация v2 пока не настроена.

На машине, где создавался scaffold, Node.js установлен локально в игнорируемую `.tools/`.
Если `node` и `npm` ещё не доступны в PowerShell, выполнить из корня репозитория:

```powershell
$env:Path = (Resolve-Path '.tools/node-v24.21.0-win-x64').Path + ';' + $env:Path
npm.cmd run dev
```

Эта локальная копия Node.js не входит в Git. На другой машине нужно установить Node.js отдельно.

## Проверки

| Команда | Назначение |
| --- | --- |
| `npm run check` | Синхронизация коллекций и проверка Astro/TypeScript |
| `npm run check:content` | Проверка схем контента и генерация типов через `astro sync` |
| `npm run build` | Production build и поисковый индекс Starlight |
| `npm run check:links` | Проверка внутренних `href`/`src` и HTML-якорей в готовом `dist/` |
| `npm test` | Тесты Markdown, курсов, Obsidian-шаблонов и draft: dev-просмотр и production-сборки |
| `npm run check:authoring` | Проверка готовой демонстрационной страницы, кода, изображения и шрифтов |
| `npm run validate` | Тесты, типы/контент, сборка, ссылки и проверка готовой страницы последовательно |
| `npm run preview` | Просмотр готовой сборки по тому же локальному адресу |

Проверки ссылок и готовой страницы требуют предварительной сборки. Проверка ссылок учитывает `site` и `base` из
`astro.config.mjs`, но не проверяет внешние сайты, ссылки, создаваемые JavaScript,
или URL внутри CSS и `srcset`.

## Границы Task 1–3

- Индексы учебника и инструкций находятся в коллекции Starlight `docs`.
- Главная, список курсов и страницы курсов — отдельные Astro-страницы со стандартным `StarlightPage`.
- Страница `404.astro` также использует `StarlightPage`: она задаёт canonical на реальный
  `404.html`, поскольку стандартный 404 Starlight 0.42.4 при `trailingSlash: 'always'` указывает на `/404/`.
- `courses` (YAML) содержит один демонстрационный манифест `ml/2026-fall.yaml`.
- `notes` (Markdown/MDX) пока пуста; предупреждение `astro sync` ожидаемо до появления материалов.
  Для authoring добавлены минимальные список `/notes/` и страницы заметок с фильтрацией черновиков.
- Starlight также предупреждает об отсутствии необязательной коллекции пользовательских переводов `i18n`;
  встроенные русские переводы используются без неё.
- Схема starter адаптирована к Zod 4: устаревший `z.string().url()` заменён на `z.url()`.
- Историческим материалам семестры не назначены. Заметки пока не публикуются.
- MDX поддерживается встроенной интеграцией Starlight; обычные страницы остаются `.md`.
- В Task 2 добавлена одна демонстрационная `.md`-страница: формулы KaTeX, код,
  Obsidian callout’ы, локальная SVG-иллюстрация, таблица и сноска.
- В Task 3 добавлена генерация курсов из YAML: статус, семестр, модули и ресурсы по ролям.
  Демонстрационный `2026-fall` взят из спецификации; историческим материалам семестр не назначен.
- Модули нумеруются по позиции в `modules`; необязательный `label` меняет только отображаемую метку.
  Организационные документы вынесены в `pages`, отдельно от раздела «Учебная программа».
  Второй демонстрационный модуль ссылается на две самостоятельные страницы учебника.
- Введение и линейные модели после Task 4B содержат реальные черновики учебника;
  Git и задание №3 остаются демонстрационными заглушками.
  Внешние ссылки ведут на `example.com` и служат только примерами.
- Три организационные заглушки описывают место для обзора курса, правил оценивания и экзамена.
- Публикация заметок относится к следующим задачам.
- `site-v2-starter/` сохранён как исходная спецификация и исключён из проверки TypeScript.

Пример: <http://localhost:4321/ml-dl-course-site/guides/authoring-example/>.
Правила записи и описание небольших плагинов — в [AUTHORING.md](AUTHORING.md).
Формулы рендерятся при сборке; callout’ы используют стандартные `aside`/`details`.
Для них не добавлен клиентский JavaScript. Исходная иллюстрация хранится рядом со страницей.
Старые публичные URL сохранены; первый перенос учебных материалов описан ниже.

Демонстрационный курс: <http://localhost:4321/ml-dl-course-site/courses/ml/2026-fall/>.
В dev он также доступен через раздел «Курсы»; на время проверки миграции у него
установлен `draft: true`, и в production он не публикуется. Внутренние ссылки в `pages` и ресурсах модулей
используют `reference('docs')`. Схема модулей теперь принимает необязательный `label`
вместо `number`; новый список `pages` поддерживает семь организационных ролей.
Генератор разрешает ссылки через `getEntry()` и останавливает сборку при отсутствующем
документе, в том числе в неопубликованном модуле. Курс содержит ссылки и краткую организационную информацию;
тексты учебника в него не включаются. Формат манифеста описан в [AUTHORING.md](AUTHORING.md).

Первый вертикальный срез (Task 4): `docs/ml/lecture_02.md` разделена на шесть
самостоятельных тем и обзор в `src/content/docs/textbook/ml/preprocessing/`.
Все семь страниц — черновики; просмотр через `npm run dev`:
<http://localhost:4321/ml-dl-course-site/textbook/ml/preprocessing/>.
В Task 4C шесть тем объединены обратно в одну главу без сокращений;
третий модуль демонстрационного курса теперь ссылается на эту главу.
`hw_02.md` не переносилось: исторический семестр ещё не подтверждён.
Разбиение, изображения, дефекты источника и проверки — в
[отчёте Task 4](migration/task-4-report.md); [карта маршрутов](migration/route-map.csv)
фиксирует будущий основной переход на обзор и состав разделения, не включает redirects.

Baseline учебника (Task 4B): ещё девять legacy-конспектов перенесены как крупные
draft-главы ML/DL без редакторского разбиения. Перенесены только 58 используемых
изображений, включая три GIF. Task 4C объединяет preprocessing в одну главу.
Обзор и навигация показывают два упорядоченных раздела в dev:
<http://localhost:4321/ml-dl-course-site/textbook/>.
Production исключает черновики. Состав, технические преобразования, проверки
и рекомендации — в [отчёте Task 4B](migration/task-4b-report.md).

Cleanup перед дизайном (Task 4C): в учебнике десять крупных глав;
preprocessing хранит все шесть тем в одном документе, а 13 его изображений —
в одной page-local папке assets. Штатная подсветка Python и кнопки copy

Сохранность и результаты проверок — в [отчёте Task 4C](migration/task-4c-report.md).

Публикация baseline (Task 6A): все десять реальных глав имеют `draft: false`
и доступны в production через обзор, sidebar и поиск. Учебное содержание сохранено.
Технические demo-страницы и заглушки остаются только в development.
Результаты проверок и URL — в [отчёте Task 6A](migration/task-6a-report.md).

Рабочая документация: [архитектура](ARCHITECTURE.md), [авторский формат](AUTHORING.md),
[инструкции для агента](AGENTS.md), [последовательность задач](CODEX_TASKS.md).

Для Obsidian откройте `src/content/` как vault и укажите `_templates` в настройках
встроенного плагина Templates. Пять шаблонов создают материалы с `draft: true`.
Черновики доступны через `npm run dev`, но исключаются из production; `npm run preview`
показывает готовую сборку без них. У курсов `draft` отвечает за публикацию независимо
от `status`. Перед публикацией измените `draft` на `false` и запустите `npm run validate`.
Пошаговая настройка и правила ссылок на черновики — в [AUTHORING.md](AUTHORING.md).

Scaffold подготовлен на основе официального шаблона
[`create astro --template starlight`](https://starlight.astro.build/getting-started/).
Коллекция `docs` использует публичные `docsLoader` и `docsSchema`
([официальная конфигурация](https://starlight.astro.build/manual-setup/)).

## Дизайн-концепции (Task 5A и Task 5B.1)

Доступны четыре обратимые темы: Editorial, Technical, Research и Research Brown.
Текущий preview использует Research Brown. Исходные три темы сохранены без изменений.
В `src/styles/design.css` измените одну строку `@import './themes/research-brown.css';`,
заменив имя на `editorial.css`, `technical.css` или `research.css`.
Импорт `shared.css` сохраняется. Dev-сервер применит изменение автоматически;
light/dark переключается штатно в Starlight.
Для проверки реальных draft-глав используйте `npm run dev`, а не production preview.
После смены темы для production preview нужна новая сборка.

Исходные концепции, токены и шрифты — в [отчёте Task 5A](design/task-5a-report.md).
Коричневая палитра, контраст, результаты проверок и локальные URL — в
[отчёте Task 5B.1](design/task-5b1-report.md).
