## Исходные данные

Вы — аналитик небольшой компании по продаже ювелирных изделий. У вас есть характеристики бриллиантов, и нужно решить две задачи:

- **Классификация:** предсказать `high_cut` — относится ли огранка к категориям **Ideal** или **Premium** (`1`), либо к остальным (`0`). Это учебное объединение категорий, а не независимая геммологическая сертификация.
- **Регрессия:** предсказать `price_usd` — стоимость бриллианта в долларах США.

Обе задачи решаются **на одном CSV-файле** `diamonds_hw01.csv` (12 000 строк). Используйте один и тот же набор признаков в обоих случаях. Столбцы `high_cut` и `price_usd` **никогда не включаются в признаки `X`**, даже при решении другой задачи.

| Столбец | Что означает | Роль |
|---|---|---|
| `carat` | масса в каратах | числовой признак |
| `depth_pct` | относительная глубина, % | числовой признак |
| `table_pct` | относительная ширина площадки, % | числовой признак |
| `length_mm`, `width_mm`, `height_mm` | геометрические размеры, мм | числовые признаки |
| `color` | категория цвета (буквы D–J) | категориальный признак |
| `clarity` | категория чистоты | категориальный признак |
| `high_cut` | 1 — Ideal/Premium, 0 — другие категории | **цель классификации** |
| `price_usd` | цена, USD | **цель регрессии** |

**Происхождение:** учебная подвыборка из открытого набора `diamonds` (`ggplot2` / `plotnine`). Взяты 12 000 реальных записей; строки с нулевыми геометрическими размерами исключены; в три признака искусственно добавлены небольшие доли пропусков для отработки предобработки. Оригинальные значения остальных полей сохранены. Подробности — в [описании данных](/ml-dl-course-site/downloads/intro-ml-dl-pish/2026-fall/hw01/DATASET_README.md). Источник: https://ggplot2.tidyverse.org/reference/diamonds.html

## Задача 2. Подготовить данные без утечки

В шаблоне уже есть разбиение на **train (60%), validation (20%), test (20%)**. Для обеих задач используются **одни и те же строки** в каждой части.

Соберите предобработку в `ColumnTransformer`:

- **Числовые признаки:** `SimpleImputer(strategy="median")` → `StandardScaler()`.
- **Категориальные признаки:** `SimpleImputer(strategy="most_frequent")` → `OneHotEncoder(handle_unknown="ignore")`.
- Объедините обработку с моделью в `Pipeline` и обучайте пайплайн только на `train`.

> [!WARNING] Важно
> Нельзя заполнять пропуски по всей таблице **до** разделения на train/validation/test: тогда информация из отложенных данных попадёт в обучение.

## Задача 3. Классификация

Обучите на `train` и сравните на `validation`:

1. `DummyClassifier` (бейзлайн);
2. `LogisticRegression`;
3. `DecisionTreeClassifier`;
4. `RandomForestClassifier`.

Вычислите **Accuracy** и **F1-macro** (`average="macro"`). Итоговую модель выберите по **F1-macro на validation** (чем больше, тем лучше).

## Задача 4. Регрессия

Обучите на **тех же признаках и строках**:

1. `DummyRegressor` (предсказывает среднюю цену);
2. `LinearRegression`;
3. `DecisionTreeRegressor`;
4. `RandomForestRegressor`.

Вычислите **MAE** (средняя абсолютная ошибка в USD; чем меньше, тем лучше) и **R²** (коэффициент детерминации; чем больше, тем лучше). Итоговую модель выберите по **MAE на validation**.
