### Исправление действующей подсветки

Найденная причина `plaintext` в предыдущем baseline не связана с Markdown:
при включённом `rawHtml` установленный Satteri пересобирает HAST и теряет
`code.data.lang`, сохраняя `className: language-python`.
Текущий bridge Expressive Code читает `data.lang`.

Добавлен небольшой `src/plugins/code-language.ts` через публичный
`defineHastPlugin` Satteri, подключённый в `astro.config.mjs`.
Он восстанавливает metadata языка из уже существующего `language-...` класса,
оставляя неизвестные языки неопределёнными. Исходный код и язык не угадываются.
Декларация `ElementData.lang` обеспечивает проверку типов.

Это адаптация metadata перед штатным Expressive Code. Собственные Shiki theme,
палитра, CSS кода, зависимости и клиентский код не добавлялись.
Версии Astro/Starlight и библиотек не обновлялись.

Production HTML из изолированной публикационной копии содержит три
`data-language="python"` блока с токенами и двумя штатными наборами цветов.
Браузер подтвердил различимость keywords, комментариев, строк и identifiers:

Длинные строки прокручиваются внутри блока; горизонтального overflow страницы
нет. Проверены все три штатные copy buttons в четырёх сочетаниях темы/ширины:
12 кликов, исходный payload без изменений, состояние «Скопировано!».
В автоматизированном браузере Clipboard API заменён локальным приёмником:

## 9. Дефекты источника, оставленные без исправления

Наблюдения требуют отдельной редакторской проверки:

- Первый Python-пример: docstring после `class` не имеет требуемого отступа.
  Исходный пример синтаксически некорректен; код не исправлялся и не исполнялся.
- Аннотация `fit(...)->None` расходится с последующим `return self`.
- В описании timestamp указана величина порядка `1.7 × 10^10` секунд;
  её следует сверить с подразумеваемой датой.
- One-hot иллюстрация показывает пять исходных строк и четыре выходных;
  названия цветов в пояснении также расходятся с изображением.
- Объяснение времени как категории говорит о часах, иллюстрация — о месяцах.
- Раздел IQR вложен в «Что делать с выбросами?»; описание Q2 и формула с Q3
  требуют проверки согласованности.
- Критерий «меньше 5%» не уточняет однозначно удаление строки или столбца.
- Шаг kNN говорит об использовании «соответствующих пропущенных значений»;
  формулировку следует проверить.
- Запись условной вероятности в MNAR остаётся обычным текстом, как в источнике.
- Сохранены опечатки, например «Выявление и выбросов аномалий», «Competely»,
  «Подчеркнем еще рах», «ворклфоу», «двуз».

Часть наблюдений уже зафиксирована в Task 4. Ошибки и опечатки не исправлялись
при объединении. Остальные замечания к исходным главам см. Task 4B.
